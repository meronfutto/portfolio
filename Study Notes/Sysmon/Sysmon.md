**Sysmon (System Monitor)** – бесплатный инструмент для подробного наблюдения за работой системы. Его разработали Марк Руссинович и Томас Гарнье при участии Дэвида Маньотти, Марка Кука, Роба Мида, Джулии Биаджини, Алекса Михаюка, Кевина Шелдрейка и Джона Ламберта.

Изначально Sysmon создали для внутреннего использования в Microsoft. Сейчас специалисты по информационной безопасности широко применяют его, чтобы лучше видеть, что происходит в системе, и обнаруживать необычное поведение или возможные угрозы.

Sysmon отслеживает и записывает различные события: запуск процессов, сетевые подключения, изменения файлов и разделов реестра. Эти журналы особенно полезны при расследовании инцидентов и поиске угроз.

Sysmon для Windows поддерживает системы с архитектурой ARM, x64 и x86. В комплект входят три исполняемых файла:

- **Sysmon.exe** — для 32-битных систем x86;
- **Sysmon64.exe** — для 64-битных систем x64;
- **Sysmon64a.exe** — для 64-битных систем ARM64.

Установка и настройка выполняются через командную строку. После установки Sysmon записывает события в журнал **Microsoft-Windows-Sysmon/Operational**.

Когда Sysmon замечает действие в Windows, он записывает его в журнал и ставит **Event ID – номер типа события**.

Например:

- **1** — запустился процесс;
- **3** — процесс установил сетевое соединение;
- **11** — создан файл;
- **22** — выполнен DNS-запрос.

В самой записи будет не только номер, но и детали: время, имя процесса, путь к файлу, адрес соединения и так далее. **Номер помогает быстро понять, на что смотреть.** При этом событие само по себе не означает атаку: например, браузер тоже создаёт процессы и сетевые соединения.

**ID 255 — это ошибка в работе самого Sysmon**, например он не смог выполнить какую-то операцию. Это не код «обнаружена атака». Если увидишь 255, нужно прочитать текст конкретной записи и выяснить, что пошло не так.

Sysmon состоит из службы и драйвера; они собирают сведения о действиях в системе и записывают события для последующего анализа.

Процесс – запущенная программа со своими ресурсами: памятью, открытыми файлами и правами доступа.

Поток – это последовательность команд, которую выполняют внутри процесса. У процесса есть хотя бы один поток, но их может быть несколько. Главное различие, что процессы имеют отдельную память, а потоки одного процесса используют общую память.

Родительский процесс – процесс, указанный как родитель, при создании другого процесса.

PID(ProcessID) – номер процесса в Windows. После завершения процесса, его номер может позже получить другой процесс.

ProcessGuid – идентификатор экземпляра процесса, который записывает sysmon. По нему удобно связывать создание процесса, сетевую активность и другие события.

**EXE, DLL, image**

EXE обычно запускает программу.
DLL содержит код и данные.
image – исполняемый образ:
1) Image – показывает путь к исполняемому файлу процесса
2) ImageLoaded – путь к модулю, к-ый процесс загрузил в свою память. Чаще всего это DLL: файл с кодом, которым программа пользуется во время работы.
3) SourceImage и TargetImage – процесс к-ый совершает действие и процесс на к-ое направлено действие соответственно.

**Пользователь и права.**

User – учётная запись, от которой выполняется действие.

SID – идентификатор учётной записи или группы в Windows.
Группа Windows – набор учётных записей, которым удобно назначать общие права.

Токен доступа в Windows – Это данные, по которым система определяет, от чьего имени работает процесс и что ему разрешено. т.е набор сведений, к-ый определяет кто запускает процесс и с какими правами.

IntegrityLevel – уровень целостности процесса в Windows. Он записан в токене доступа и помогает системе ограничивать действия процесса. Low, medium, high, system. Обычная программа пользователя работает на уровне medium, программа запущенная от имени администратора на уровне high. Главное правило: процесс с более низким уровнем не может изменять объект более высокого уровня.

**Служба, драйвер и ядро**

Служба – это программа, к-ая система запускает для выполнения фоновой задачи. Её работой управляет Windows Service Control Manager, т.е сама Windows, а не пользователь.

Ядро – это привилегированная часть ОС, которая управляет процессами, памятью, вводом-выводом и другими базовыми механизмами.

Драйвер – компонент, работающий с механизмами ОС или устройствами. Не каждый драйвер связан с физическими компонентами. Драйвер Sysmon помогает наблюдать системную активность.

**Handle и Callback**

Handle(дескриптор) – выданная ОС-ой ссылка на объект: файл, процесс и т.д.. Через неё программа обращается к определённому объекту с определёнными правами.

Callback – это функция, которую передают другому компоненту со смыслом "когда произойдёт нужное событие, вызови эту функцию"

**Хэш и цифровая подпись**

Хэш – это результат вычисления по данным файла. SHA-256 помогает сравнивать содержимое: изменение файла обычно меняет его хэш.

IMPHash – это отпечаток списка функций, которые программа собирается брать из других файлов, обычно DLL.

Цифровая подпись – позволяет проверять две вещи: кто подписал файл и изменилось ли его содержимое после подписания. Подписанный файл может быть вредоносным и использоваться во вред.

**Реестр, WMI и named pipe.**

Реестр – иерархическое хранилище настроек Windows и приложений.

**WMI** (_Windows Management Instrumentation_) — это механизм, через который программы и администраторы могут **запрашивать сведения о Windows и управлять некоторыми её компонентами**.

Named pipe (именованный канал) – механизм обмена данными между программами.

**КАК SYSMON НАБЛЮДАЕТ ДЕЙСТВИЯ?**

В Windows у sysmon есть две основные составляющие: драйвер и служба.

На картинке показан путь **от действия до записи в журнале**. Возьмём одно действие: запуск `notepad.exe`.

1. **Windows создаёт процесс.**
2. **Драйвер Sysmon** — часть Sysmon, работающая близко к ядру Windows — получает сведения об этом действии.
3. **Sysmon обрабатывает сведения:** собирает нужные поля и применяет настроенные правила.
4. **Служба Sysmon** участвует в этой работе и записи результата в **журнал событий Windows**.
5. В журнале появляется событие, которое можно открыть и прочитать.

То есть **драйвер помогает заметить действие, а служба помогает превратить сведения о нём в запись журнала**. Это упрощённая схема: конкретная обработка может происходить в разных компонентах Sysmon.

Строка «фильтрация» означает: Sysmon может быть настроен записывать только выбранные события. Он не обязан заносить в журнал вообще каждое действие на компьютере.

**УВЕДОМЛЕНИЯ ЯДРА**
Драйвер заранее регистрирует функции-обработчики (callbacks). Когда в Windows происходит нужное действие, например создание процесса, система вызывает соответствующий обработчик.
PreOperation – вызов перед операцией
PostOperation – вызов после операции
SysmonDrv.sys + 0x.... – адрес функции внутри драйвера

**МИНИФИЛЬТР ФАЙЛОВОЙ СИСТЕМЫ**

Минифильтр – это драйвер, который может наблюдать за запросами к файлам по пути к файловой системе. Для sysmon он даёт возможность получать сведения о выбранных файловых действиях.

**Altitude** — это число, которое задаёт **место минифильтра среди других минифильтров** при обработке файлового запроса.

Например, есть два минифильтра: один с altitude `380000`, другой с `320000`. Когда программа просит открыть файл, Windows сначала вызывает обработчик **перед операцией** у фильтра с большим altitude, затем — с меньшим. После выполнения запроса обработчики **после операции** вызываются в обратном порядке.

**ETW**

ETW (Event Tracing for Windows) – механизм Windows для получения событий от поставщиков телеметрии. Это отдельный способ для sysmon фиксировать события.

Драйвер может начать наблюдение раньше пользовательской службы. Ранние события временно сохраняются, затем служба записывает их в журнал. Это повышает видимость при загрузке, но не даёт гарантии отсутствия любых потерь.

### Справочник команд

| Команда                          | Что делает                                     |
| -------------------------------- | ---------------------------------------------- |
| `.\Sysmon64.exe -?`              | Показывает справку                             |
| `.\Sysmon64.exe -? config`       | Показывает помощь по конфигурации              |
| `.\Sysmon64.exe -s`              | Печатает поддерживаемую схему                  |
| `.\Sysmon64.exe -c`              | Показывает текущую конфигурацию                |
| `.\Sysmon64.exe -i`              | Устанавливает Sysmon                           |
| `.\Sysmon64.exe -i .\config.xml` | Устанавливает с указанной конфигурацией        |
| `.\Sysmon64.exe -c .\config.xml` | Применяет конфигурацию к установленному Sysmon |
| `.\Sysmon64.exe -u`              | Удаляет Sysmon                                 |
**Важно:** `-c .\config.xml` — применение набора настроек, а не безопасное «добавление одной строчки» к прежним правилам. Перед заменой сохраняют исходный XML и возможность отката. Вывод `-c` не следует автоматически считать готовой резервной копией XML.
